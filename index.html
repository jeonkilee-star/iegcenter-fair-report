  1. 1. 네트워크/API 실패 (9/2 12% → 9/3~9/4 22%로 악화)
    초반엔 안정되는 듯했으나 이후 이틀간 오히려 실패율이 늘었습니다. 부스 근처 Wi-Fi 혼잡/장애 여부를 확인하고, 가능하면 유선랜이나 전시업체 전용망으로 전환하는 게 가장 빠른 완화책입니다. 근본적으로는 앱의 API 요청 타임아웃이 기본값(10초)으로 짧게 잡혀 있고 실패 시 재시도 로직이 없는 게 원인이라, 타임아웃을 늘리고 1회 자동 재시도를 추가하는 코드 수정이 실질적인 해결책입니다.
  2. 2. 짧은 잡음("아/어/이")과 지나가는 잡담에 매번 반응하는 문제

  3. 3. 인스트럭션 변경이 앱 재시작 전까지 반영 안 되는 문제
    사람이 재시작 버튼 위치를 기억해야 하는 방식 대신, 앱이 주기적으로(예: 10~30분마다) 서버에서 최신 설정을 자동으로 다시 받아오도록 코드를 바꾸면 현장에서 아무도 신경 쓸 필요가 없어집니다.
